# 論理と根拠を点検する手順

内容を変えたら、本文だけでなく、その変更に依存する矢印とストーリーも点検します。CIは構造の矛盾と未点検の版を検出します。文章の論理や研究の解釈を自動で証明する仕組みではありません。

## 1. 変更の意味を定める

変更する項目・矢印のIDを決め、「誰が、何を、どの条件でできる／行う／失うのか」を書きます。能力、行動の傾向、アクセス権、防御、被害を分けてください。

次の問いに答えます。

1. **仕組み**：前の状態から、何が変わると次の状態になるか。
2. **成立条件**：一緒に必要な条件はどれか。代替できる経路はどれか。ANDは組み合わせ、ORは重なり得る別の仕組みとして表す。
3. **反例**：前の状態が成立しても次が起きない場面を一つ具体的に挙げる。その場面を除く条件が図や本文にあるか。
4. **一次情報との対応**：誰が調べた何が、この主張のどの部分を支持するか。URLだけでなく該当箇所を書く。
5. **限界**：何が未観測・未評価か。反対の結果や異なる条件は何か。「見つからない」を「起きない」へ変えていないか。
6. **対策**：どの条件に作用する対策か。有効性を測った結果と、考えられる候補を分ける。

ANDの条件が別々の実験で観測されても、同じ場面で同時に成立した証拠にはなりません。ORは相互排他とは限りません。分類の包含関係を、時間の前後関係へ置き換えないでください。

## 2. 一次情報を確認する

研究は原論文・評価者の原報告、事件は実際に調査した組織の報告、制度や理論は制定主体・提案者の原資料を使います。著名人の発言は「その人がそう述べた」という主張の一次情報にしかなりません。レビュー論文、記事、Deep Researchの文章は資料を探す入口にとどめます。

`content/research.json` に評価者、モデル・版、対象時期、設定、測定方法、結果、限界、出典IDと該当箇所を記録します。開発企業自身の報告と、第三者が実施した評価を区別します。開発企業のカードに収録された外部評価を、その外部機関の原データまで独立確認したとは記述しません。

数字は母数・単位・試行回数を確認します。課題の一度以上の成功、全試行の平均成功率、部分点、利用率、利益は別の指標です。安全制約を外した能力評価を、通常提供の利用条件へ置き換えません。古い観測期間を、最新モデルの能力上限として使いません。

## 3. 本文と点検記録を更新する

ノードは `概要 / 他の条件との関係 / 現在の状況 / 成立条件 / 根拠の限界 / 考えられる対策` の6節で書きます。「成立条件」は現象が起きるための条件、「根拠の限界」は判断できない範囲です。両者を「残る壁」にまとめません。[日本語の書き方](japanese-writing-guide.md)も確認します。

本文・グラフ・一次資料・ストーリーを直した後、次を実行します。

```sh
npm run review:draft -- --id=2026-09-10-short-subject
```

`docs/reviews/` に未点検の草案ができます。既存の点検記録は上書きしません。`assessments` の6項目と `primary` の出典・該当箇所・支持する範囲を記入し、各 `entries` を該当する評価へ割り当てます。一つの論点に関する複数の項目は、同じ評価を参照できます。

根拠を確認してから `reviewer` と `date` を記入し、`decision` を `reviewed` に変更します。**草案を生成しただけでは点検済みになりません。** 誤字修正でも、その語の変更が意味を変えない理由を短く記録します。意味が変わる場合は `history.json` にも変更前・変更後・理由を残します。

`reviewed` は記録した担当者による編集上の点検を表します。独立した専門家の査読や、GitHub上の承認者の署名ではありません。PRの内容レビューは別途行います。

## 4. CIで照合する

```sh
npm run check
npm run build
```

次の不整合や未点検を検出すると、CIと公開ビルドが失敗します。

- 未定義ID、欠けた説明・一次出典・研究カード、誤った日付。
- 入力のないAND、下位図のAND／ORとの矛盾、並列の兄弟を前後関係にする線、未明示の因果循環。
- 登録した項目の描き忘れ、重複、孤立、カードの重なり、主要な線の重なり。
- 本文や出典の版に対応する点検記録の欠落。

点検対象の指紋には、参照する研究や出典も含めます。研究の結果が変われば、その研究を使うノード、そのノードに接続する矢印、関係する図・ストーリーの記録も古くなります。項目の追加・削除では一覧の指紋も変わります。出典のリンク確認だけを行った日と、内容の再点検日は別です。

今回の訂正は回帰テストにしています。例えば「全労働の技術的代替を、働かず暮らせるための必須条件に戻す」「金融危機を貨幣の消滅へ直結する」という変更は検出します。これらは現在の編集方針を守る検査です。新しい根拠によって枠組みを変える場合は、理由を記録した上で検査もレビューしてください。

CIは、URLの内容が主張を本当に支持するか、反例の検討が十分か、全ての研究を網羅したかまでは判断できません。ハッシュだけを更新する作業で点検を代用しないでください。履歴には、以前の判断を誤魔化さず残します。
