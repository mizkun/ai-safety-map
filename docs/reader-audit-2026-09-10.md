# 初めて読む人に必要な前提と、説明のつながりの点検

点検日：2026-09-10。担当：Codex。独立した専門家による査読や、読者を募集した理解度試験ではありません。

## 対象と結果

76項目の6節、41本の矢印、8経路に属する28章、44件の研究カード、46語の用語集を読み、話題の目的、主語、仕組み、先に必要な知識、例外、根拠の範囲を確認しました。8経路のうち研究・自己改善は他の経路に関わる要因として保持され、ツアーのシナリオ一覧は7経路です。

説明を変更したのは31項目、27本の矢印、18章、7件の研究カード、1語です。計100の本文フィールドを日英で対応させ、ツアーの開始文と変更履歴も更新しました。変更していない箇所は、既に役割や条件を説明している、または研究の設定・結果・限界が具体的に示されているため保持しました。

ノードの集合、AND／OR、因果関係の接続先、評価結果の数値、出典の記録は変更していません。以前の図を説明していたR2/R4の文章と、実行後の対処だけに偏っていたM3の説明は、現在の項目の意味に合わせて訂正しました。

## 主な不足と対応

| 論点 | 読み手が迷う理由 | 対応 |
| --- | --- | --- |
| ASIと現実への影響 | なぜ能力の話の途中で「現実へ影響する」条件が出るのか分からない | 制御喪失の経路の目的を最初に説明。AIの判断が道具の操作や人の行動に届くこと、監督する側との能力差を確かめることを先に置いた。その後でASI以外の道や安全性研究を示す |
| 研究・自己改善 | 一作業の高速化と開発全体の加速が混ざり、説明に古い接続先も残っていた | 資料・コード・実験・確認という工程を例示。R2/R4の関係を現在のR0起点に合わせ、RSIが止まらない加速や完全自律を意味しない点を保持 |
| アライメントと監督 | 評価点、目的、実行、監督が何を指すかが省略されていた | 学習の評価点を説明し、苦情を閉じるだけの仮定例を追加。実行する道具・権限・人間の採用と、行動記録を点検する監督を具体化 |
| 能力評価から悪用への移行 | 「現実に近い」「ベンチマーク」「CCL」が未説明で、試験と被害をつなぐ条件が見えにくい | 評価環境の複雑さ・防御・道具・情報・人の支援を説明。利用者の支援、対象への接点、防御を別々に確認する構成へ整理 |
| 軍事・競争 | 一つのAIの反乱と、AIを使う当事者同士の反応が区別しにくい | 最終判断をする人・組織、確認する時間、誤認への相互反応を先に説明 |
| 事故と復旧 | 同時に起こる障害と、障害の伝播が混ざりやすい | 在庫・発注・配送を説明用の仮定として追加。復旧に必要な電力や通信まで失うと長引く理由を説明 |
| 社会的依存 | 委任がなぜ主導権の喪失につながるのかが薄い | 代替へ移れないこと、異議が決定に届かないこと、制度を作り直せないことを段階として説明 |
| 仕事と暮らし | 能力、職業の曝露、失業、分配が混同されやすい | 曝露と補完を説明し、できること・実際の導入・再就職・生活必需品を得られることを分けた |
| 所得と貨幣 | AIの出力、売上、純利益、誰の所得かが飛躍しやすい | 対価を払う相手、取引の完了、所有と分配を説明。価格が誰に物を配るかを決める役割を述べてから、その役割の縮小という仮説へ進む |
| 金融危機 | 株価下落から貨幣や暮らしの崩壊へ話が飛びやすい | 売りと価格下落の循環、損失吸収と流動性、貸し出し・決済、信用の回復と代替、仕入れ・輸送への波及をつないだ |
| 対策 | 「監督・評価を改善する」という一般論では、何に効くか分からない | 10本の矢印で、残る職務、価格への還元、非就労者の所得、独立した決済、研究成果の別課題検証など、条件への作用先を具体化 |

具体例を追加した箇所では、仮定を観測事実として扱っていません。「必ず起きない」「現在はできない」といった新たな断定も加えていません。

## 一次情報との照合

改訂で意味が変わり得る箇所を、次の原資料で照合しました。元からある全ての研究の全文を、この点検で最初から再調査したという意味ではありません。44件の研究カードの設定・結果・限界は全件読み、以下では今回の変更に関わる定義と根拠を再確認しています。

- [DeepMindの安全性の原枠組み](https://arxiv.org/html/2504.01849v1)：能力差、開発の加速、悪用・ミスアライメント等の区別、安全性研究へのAI活用。原論考の仮定を、観測された破局や確率に置き換えていない。
- [Specification gaming](https://deepmind.google/blog/specification-gaming-the-flip-side-of-ai-ingenuity/) と [goal misgeneralization](https://deepmind.google/blog/how-undesired-goals-can-arise-with-correct-rewards/)：評価点と目的の差、適切な報酬でも環境変化で別の目標が表れる違い。後者の案内役を追う原例も確認した。
- [METRの時間地平評価](https://metr.org/time-horizons/) と [AI Control原論文](https://arxiv.org/abs/2312.06942)：人間の所要時間という尺度と、監督・編集・監査という運用手順の意味。
- [Anthropicの自動安全性研究](https://www.anthropic.com/research/automated-researchers-mitigate-alignment-failures)：限定課題の評価を、安全性全般の確立としない。
- [Astra System Card](https://deploymentsafety.openai.com/gpt-6-astra)、§10.1.2：既知の41課題・各5試行・到達度100%、別評価の9/10課題と平均59%等を保持。過去の脆弱性情報への接触による過大評価の懸念を、平易な文章へ直した。
- [Gemini 3.7 Flash Model Card](https://deepmind.google/models/model-cards/gemini-3-7-flash/)、Frontier Safety Assessment：CCLの警戒水準と本体の区別、専門家誘導と評価認識の限界を保持。
- [Gradual Disempowerment原論文](https://arxiv.org/html/2501.16946v2)：依存する制度を変える力が弱まるという仮説を、AIの反乱と区別。
- [ILOの職業曝露研究](https://www.ilo.org/publications/generative-ai-and-jobs-refined-global-index-occupational-exposure) と [米国国勢調査局の原分析](https://www.census.gov/library/working-papers/2026/adrm/CES-WP-26-25.html)：曝露を失業に換算せず、企業数と雇用による重み付けの違いを説明。
- [Anthropicの経済シナリオ原資料](https://www.anthropic.com/institute/econ-scenarios)、Table 3：GDP +32.4%、知的職業の賃金 −11.5%、全体失業率11.9%は、最も変化が大きい仮定の計算。発生確率でも観測値でもない。
- [Visa・Artemisの機械決済分析](https://www.visa.com/en-us/thought-leadership/innovation/agentic-payments-from-the-ground-up)：ブロックチェーンに記録された取引の範囲と、認可・支出管理を確認。MPPを含む全ての決済がその範囲に限られるとはしない。
- [FSBの原報告](https://www.fsb.org/2024/11/the-financial-stability-implications-of-artificial-intelligence/) と [BoE・FCAの2024年調査](https://www.bankofengland.co.uk/report/2024/artificial-intelligence-in-uk-financial-services-2024)：共通依存・相関と、組織の利用率75%／用途の完全自律2%という異なる母数。
- [ECBの貨幣の解説](https://www.ecb.europa.eu/ecb-and-you/explainers/tell-me-more/html/what_is_money.en.html) と [決済戦略](https://www.ecb.europa.eu/pub/pdf/other/ecb.eurosystemcomprehensivepaymentsstrategy202603.en.pdf)：貨幣の機能と代替決済の役割。AIで貨幣の配分機能が縮小するという仮説をECBの予測とせず、デジタルユーロの計画を導入済みとしない。

## 次の変更でも確認する手順

1. `npm run review:reading` で日英の実際のツアー順と単独で開く詳細を出力する。
2. 用語集を開かず、順に読む場合と途中の項目から読む場合を確認する。
3. `npm run review:draft -- --id=YYYY-MM-DD-subject` で新しい点検記録を作る。
4. 仕組み・条件・反例・根拠・限界・対策に加え、`readerContext` と `whyHere` を記入する。
5. 原資料との対応と日英の意味を確認してから点検済みの版を記録し、`npm run check` と `npm run build` を実行する。

今回の[点検記録](reviews/2026-09-10-reader-prerequisites.json)は、変更に依存する図やニュース等を含む140単位を、9つの論点ごとに記録しています。自動検査は記入漏れや古い版を検出しますが、理解しやすさや論理の妥当性を証明しません。

- `npm run build`：静的ページの生成と、GitHub Pages用の11件の入口アセットの確認が成功。ビルドは公開操作ではない。

- 読む順番の出力は日英それぞれ115場面。日本語のASIの詳細で、理由の説明と例外の段落が分かれて表示されることを確認。
- 1920 × 1080の全要素マップでは、日英とも83枚（76項目と7経路）の項目名を表示し、文字領域のはみ出しなし。全図に合わせると文字は小さくなるが、IDだけに切り替わらない。
- 1440 × 900のPCツアーと320 × 740のスマホツアーを画面で確認。スマホのEnter操作は次の章へ切り替わり、本文のスクロール位置は先頭、ページの横はみ出しなし。

検査中に、英語の「five attempts」と「5 attempts」など、意味が同じでも古い文字列検査が失敗する箇所が見つかりました。試行数は数字の表記に揃え、攻撃成功率との区別は自然な言い換えを許容しました。「収入から貨幣不要への直接の矢印がない」という検査は、決まった文章の有無から、翻訳後の図の接続の検証へ変更しました。
