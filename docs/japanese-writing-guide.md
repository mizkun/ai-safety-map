# 日本語の説明文を点検する

このサイトでは、短さより「誰について何が分かったか」が一読で分かることを優先します。専門用語は必要なら使い、タップで説明を読めるようにします。

主な根拠は、文化審議会の[「公用文作成の考え方」](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93731901_01.pdf)（2022年1月7日、特に本文32〜34ページ）です。以下は、その考え方をこのサイトへ適用した編集手順です。文字数は機械的な合否基準にしません。

## 主語と述語

主語が何を指すかを先に決め、述語を対応させます。「報告は高い能力です」のように、報告と能力を混ぜません。評価者、評価されたモデル、利用者、人類を同じ文の中ですり替えないでください。

例：

- 改訂前：「Astraの報告は、サイバー能力の伸びを示します。」
- 改訂後：「OpenAIはAstraを複数の課題で評価しました。能力の伸びを報告していますが、通常提供とは異なる設定を含みます。」

全ての文に主語を足す必要はありません。読み手が迷う場所では具体的な名詞を書きます。受け身も禁止しませんが、「評価されています」だけで終えず、誰の評価かを示します。

## 一文で扱うことを絞る

一文に結論、方法、例外を詰め込まず、結論、根拠、限界へ分けます。長い文は見直す目印ですが、文字数だけで切って論理を失わないようにします。

修飾語は、かかる名詞の近くへ置きます。「通常提供とは異なる、Astraの能力を調べた設定」より、「Astraの能力を調べるための、通常提供とは異なる設定」の方が関係を追いやすくなります。

## 接続詞は論理に合わせる

「そのため」は因果関係、「ただし」は範囲の限定、「一方」は比較に使います。二つの事実があるだけで「そのため」とつながないでください。

例：「AIを使う企業が増えた。そのため、人間の仕事がなくなる」は飛躍です。「AIを使う企業が増えた。ただし、利用率は職務全体の代替率ではない」と区別します。後の状態へ進む追加条件は、別の文で具体的に示します。

## 指示語の参照先

「これ」「その条件」「一つの試験」と書いたら、読み手が参照先を一つに決められるか確認します。直前に複数の候補があるなら、名詞を繰り返します。

例：「一つの試験結果からは言えません」では、何の試験が一つしかないのか不明です。Astraには複数の評価があるため、「この100%は、既知の41課題を各5回試した際の到達度です。現実の攻撃の成功率ではありません」と、数値の対象を特定します。

## 書き直しても根拠を変えない

「一部でできた」を「できる」に、「観測していない」を「できない」に変えません。「分からない」で終える場合も、対象モデル、条件、比較、未確認の範囲を示します。比喩で分かりやすくしても、元の主張より強い因果や確率を付け加えないでください。

点検時は、主語、述語、接続詞、指示語、修飾先、観測範囲の6点を確認します。数値・モデル名・日付・研究の限界は、読みやすさのために削り落とさず、研究カードへ整理します。

## 柔らかく読める説明にする

- まず「誰に何が起きる話か」を置き、その後に用語や条件をつなげます。状態の定義を、現在すでに起きている出来事のようには書きません。
- 「状態です」を繰り返すだけでなく、「〜したとします」「〜できるかを考えます」など、仮定する場面と確かめる問いを使い分けます。語り口を柔らかくしても、断定の強さは変えません。
- 「ただし」や「一方」で示す違いは、何と何の違いかを書きます。「それ」「こうした」だけで研究や対象を省略しません。
- ツアーの一場面では、場面の説明と、その先へ進む条件・進まない可能性を段落で分けます。段落を改めたことを、新しい因果ステップとして描きません。
- 能力評価のモデル名、数値、母数、対象時期、設定、限界は、親しみやすさのために丸めません。災害や被害の説明を茶化したり、根拠のない楽観・悲観を付け加えたりもしません。

## 前提知識と、話題のつながり

用語が分かっても、その話をする理由が分からなければ説明はつながりません。読者がAI安全性を学んだことも、用語集や別のシナリオを読んだことも前提にしません。

- 章の最初に「この経路では、誰に何が起きる可能性を見るのか」を置きます。例外を列挙する前に、その章で確かめる問いを説明します。
- 新しい条件を出したら、前の話と何がつながるのかを書きます。例えばASIの章では、「高度な判断を人間が監督できるか」が問題になる理由を先に示します。その後で、ASIでなくても重要な操作に届く場合があると説明します。
- 「現実への影響」「監督」「所得」などの普通の言葉にも、文脈次第で説明が必要です。AIの出力が道具の操作や人間の判断を通じて何を変えるか、誰が何を点検するか、お金が賃金や利益として誰に届くかまで具体化します。
- 専門用語は初出で、その場で必要な意味を添えます。用語集は詳しく知るための補助です。AND／ORや項目IDだけでつながりを説明しません。
- 具体例を足す場合は、観測された事例と説明用の仮定を明示的に分けます。後者は「例えば、〜とします」と書き、研究の実績に見せません。
- 「必ず起きるわけではない」という注意書きだけで終わらせず、何が変われば進むか、何が保たれれば進まないかを説明します。

`npm run review:reading` で、実際にツアーが表示する順番の文章と、単独で開く詳細を出力できます。最初から順に読む場合と、途中のカードへ直接入る場合の両方を確認します。未使用の導入文を直しただけでは、表示される説明を直したことになりません。
