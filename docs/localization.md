# 日本語・英語の切り替え

画面の文言はcontent/ui/ja.jsonとen.jsonに分離しています。現在の公開本文は日本語です。英語の画面文言は用意していますが、本文の翻訳・レビューが済むまでは言語メニューのEnglishを無効にします。

## 共有するもの

マップの固定ID、経路の接続、順序、出典URL、公表日、対象項目の点検日は言語間で共有します。翻訳を別の因果マップにしないためです。既存の `#map=control&node=C1` のURLも維持します。表示言語を指定する場合は `#lang=en&map=control&node=C1` の形です。

英語本文を用意するときは、原文のJSON・Markdownとは別にcontent/translations/en.jsonを作ります。

```sh
npm run i18n:export -- en
```

このコマンドは翻訳用の文言キーと空欄を出力します。既存の翻訳ファイルは上書きしません。原文の参考文とsourceHash（原文の内容を識別する値）も含みます。

## 翻訳と公開

stringsの全ての文言を翻訳します。概要／成立条件等の本文セクションの内部キーは、日本語版と共有する識別子として保持します。画面上のセクション名はui/en.jsonで翻訳されます。aliasesは英語本文中で用語解説を開ける表記を登録します。資料の正式名称は必要に応じて原題を保ってください。

用語と証拠の強さ、実験・実際の事例・仮説の区別、原文にある限界をレビューし、content/locales.jsonのen.enabledをtrueにします。npm run checkとnpm run buildが通ったPRを取り込むと、言語メニューから切り替えられます。

翻訳が欠けている、空欄がある、固定IDなど本文以外のフィールドを変更しようとする場合は検査に失敗します。日本語本文の文言が変わってsourceHashが一致しなくなった場合は、英語版の表示を自動で停止し、日本語版の公開は続けます。未点検の翻訳を最新として表示しないためです。

原文が変わったら、差分に対応する翻訳をレビューしてからsourceHashを更新してください。値だけを更新して翻訳済みとは扱いません。翻訳の修正と、その確認範囲はPRに残します。

lib/translation-fields.mjsは翻訳してよい文言だけを取り出し、構造・参照は原文から組み立てます。lib/read-site-content.mjsは公開可能な翻訳だけを読み込みます。研究カードとストーリーも翻訳対象です。scripts/validate-locales.mjsは画面文言のキーと埋め込み値、本文の公開条件を検査します。
