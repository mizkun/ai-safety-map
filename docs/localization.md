# 日本語・英語の切り替え

日本語と英語の全文を公開しています。画面右上の `JP / EN` で切り替えます。本文、研究カード、用語、ストーリー、ツアー、更新履歴を含みます。初回の英訳はCodexが原文から作成し、原文と比較して編集上の点検をしました。独立した専門家の査読を示すものではありません。

## 共有するもの

固定ID、因果関係、AND／OR、出典URL、機械判定用の日付、証拠の分類は共通です。英訳は別の因果マップを作りません。既存のURLも維持します。表示言語を指定する場合は `#lang=en&map=control&node=C1` の形です。

画面文言は `content/ui/ja.json` と `en.json`、英訳本文は `content/translations/en.json` に置きます。`reference` は対応する日本語、`strings` は英訳です。本文セクションの内部キーは共通の識別子として日本語を保ち、画面上の見出しはUI辞書で訳します。資料の正式名称は原題を保てます。

## 変更する手順

1. 原文を変更し、対応する英訳と `reference` を更新します。新しいキーの一覧は `lib/translation-fields.mjs` の `translationFields` で取得できます。別言語を初めて追加する場合は `npm run i18n:export -- en` で草案を作れます。このコマンドは既存ファイルを上書きしません。
2. 主語、条件、数値の分母、実験設定、観測と仮説、反証・限界を比較します。`aliases` には英語本文から用語説明を開ける表記を登録します。
3. 原文全体の `translationFields` をJSON化したSHA-256を `sourceHash` に記録します。値だけ更新して翻訳を済ませた扱いにしません。
4. 点検後、`review` に担当者、日付、`lib/translation-review.mjs` の `translationReviewHash(translation, sourceUi, targetUi)` を記録します。この値は英訳と日英UIも含みます。点検の範囲と判断をPRと `docs/reviews/` に残します。
5. `npm run check` と `npm run build` を通します。新しい言語を公開するときは `content/locales.json` で有効にします。

有効な英語版に未訳・古い原文参照・不正なフィールド・古い点検値があると、公開前の検査は失敗します。日本語だけを変更して古い英訳を表示し続けることはできません。日英UIのキーと埋め込み値の一致も検査します。点検値は正しい解釈の保証ではなく、確認した版との一致を検査するものです。

## 配信

初期表示には両言語の短い名称と共通の構造を含めます。詳しい本文は、選択中の言語の `details-ja-….json` または `details-en-….json` を必要になったときに読み込みます。最初から両言語の全文を取得しません。切り替えても選択中の経路と項目を保ちます。
